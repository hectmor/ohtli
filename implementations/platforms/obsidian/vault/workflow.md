# Workflow

The Ohtli Vault follows a simple workflow designed to minimize friction while keeping information organized over time.

Every piece of information enters the system in the same way and gradually moves toward its appropriate long-term location.

```text
Capture
    │
    ▼
 Inbox
    │
    ▼
 Process
    │
    ├────────► Projects
    │
    ├────────► Areas
    │
    ├────────► Knowledge
    │
    └────────► Archive
                 ▲
                 │
      Completed Projects
```

## Principles

The workflow is based on five principles:

1. Capture quickly.
2. Organize intentionally.
3. Maintain active work.
4. Preserve useful knowledge.
5. Archive inactive material.

The goal is to spend as little time as possible deciding where information belongs while ensuring it can always be found later.

---

# Step 1 — Capture

Capture information immediately without worrying about organization.

Everything starts in the **Inbox**.

Examples include:

* Ideas
* Meeting notes
* Tasks
* Links
* Quotes
* Research
* Drafts

Do not organize while capturing.

---

# Step 2 — Process

Review the Inbox regularly.

For every note, decide its purpose.

Ask the following questions:

## Is it actionable?

If yes:

* Does it belong to an existing project?
* Does it require creating a new project?

Move it to **Projects**.

---

## Is it an ongoing responsibility?

If yes:

Move it to **Areas**.

Examples:

* Health
* Career
* Learning
* Finance
* Home

---

## Is it reference information?

If yes:

Move it to **Knowledge**.

Knowledge should be reusable and independent of a single project.

Examples include:

* Documentation
* Tutorials
* Concepts
* Book notes
* Technical references

---

## Is it no longer active but still valuable?

Move it to **Archive**.

---

# Step 3 — Work

Most daily work happens inside **Projects** and **Areas**.

Projects represent temporary efforts with a defined objective.

Areas represent long-term responsibilities that require continuous maintenance.

Projects may produce new knowledge.

Knowledge may support multiple projects and areas.

---

# Step 4 — Review

The Vault should be reviewed regularly.

## Daily Review

* Process the Inbox.
* Update active projects.
* Capture new work.

## Weekly Review

* Empty the Inbox.
* Review project progress.
* Remove obsolete tasks.
* Organize recent notes.

## Monthly Review

* Evaluate active areas.
* Archive completed work.
* Identify long-term priorities.

## Quarterly and Yearly Reviews

* Reflect on completed work.
* Reorganize knowledge when necessary.
* Simplify the workspace.
* Remove outdated information.

---

# Step 5 — Archive

The Archive preserves historical context.

Archive information when:

* A project is completed.
* Material is no longer actively used.
* Notes are kept only for historical reference.

The Archive is not a trash bin.

Archived information remains searchable and may become useful again in the future.

---

# Directory Responsibilities

| Directory   | Responsibility                          |
| ----------- | --------------------------------------- |
| Inbox       | Temporary capture                       |
| Projects    | Temporary work with a defined objective |
| Areas       | Long-term responsibilities              |
| Knowledge   | Reusable reference material             |
| Journal     | Chronological records                   |
| Reviews     | Periodic maintenance                    |
| Templates   | Reusable note templates                 |
| Attachments | Supporting files                        |
| Archive     | Inactive but preserved information      |

---

# Decision Guide

When processing a note, use the following questions:

```text
Is it new?
        │
        ▼
     Inbox
        │
        ▼
Does it require work?
        │
   Yes ─────────► Projects
        │
        No
        │
        ▼
Is it a long-term responsibility?
        │
   Yes ─────────► Areas
        │
        No
        │
        ▼
Is it reusable knowledge?
        │
   Yes ─────────► Knowledge
        │
        No
        │
        ▼
Archive
```

Following this workflow consistently is more important than creating a perfect organizational structure. A simple system that is used regularly is more effective than a complex system that is difficult to maintain.
