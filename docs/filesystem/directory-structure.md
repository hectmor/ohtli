# Directory Structure

Ohtli organizes information into a small set of top-level directories.

```text
/
├── inbox/
├── areas/
├── projects/
├── knowledge/
├── journal/
├── reviews/
├── templates/
└── attachments/
```

## Directories

### inbox/

Stores unprocessed information.

---

### areas/

Contains long-term responsibilities.

---

### projects/

Contains active and archived projects.

---

### knowledge/

Stores reusable knowledge.

---

### journal/

Stores chronological records.

---

### reviews/

Stores periodic reviews.

---

### templates/

Contains reusable document templates.

---

### attachments/

Stores non-Markdown resources such as images, PDFs, spreadsheets, and other supporting files.

## Principles

* Every document belongs to exactly one primary directory.
* Directories represent domain entities, not implementation details.
* The hierarchy should remain shallow whenever possible.
