# Contribution Model

All contributions should improve the framework without compromising its principles.

## Contribution Workflow

1. Identify a problem or opportunity.
2. Open an issue.
3. Discuss the proposed solution.
4. Create a feature branch.
5. Implement the change.
6. Submit a pull request.
7. Review and merge.

## Contribution Principles

* One feature per pull request.
* Keep changes focused.
* Update documentation when necessary.
* Maintain backward compatibility whenever possible.
* Follow the project's coding and documentation standards.

## Architectural Changes

Changes affecting the architecture, domain model, metadata model, or governance require an Architecture Decision Record (ADR).

## Definition of Done

A contribution is complete when:

* Documentation is updated.
* Related ADRs are recorded if required.
* The repository remains consistent.
* All review comments have been addressed.
